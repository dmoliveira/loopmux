# v0.1.42 Milestone Plan

## Objective
- Deliver the next reliability-focused iteration after `v0.1.41` with tighter runtime clarity and safer long-running loop behavior.

## Scope
- Improve operator-facing telemetry readability for mixed active/idle windows.
- Expand deterministic regression defenses for cadence and control-state transitions.
- Keep release artifacts (`draft`, `runbook`, `changelog`) synchronized as milestone cards merge.

## Proposed Work Items
- `Card 1` Runtime signal refinement
  - Improve readability of heartbeat/health-style telemetry under long-lived sessions.
  - Preserve low-noise cadence defaults while keeping high-value triage context.
- `Card 2` Regression defense growth
  - Add focused tests for cadence edge paths and state-transition correctness.
  - Keep behavior deterministic under strict lint/test gates.
- `Card 3` Release-flow continuity
  - Keep v0.1.42 draft/runbook/changelog references current as PRs land.
  - Keep release + post-release commands ready to execute without ad-hoc discovery.

## Acceptance Criteria
- Milestone cards tracked in `br` with concise scope and validation evidence.
- Quality baseline remains green: `cargo fmt --check`, `cargo test -q`, `cargo clippy -- -D warnings`.
- Release docs are internally consistent and executable at cut time.

## Out of Scope
- Broad feature work outside runtime reliability.
- CLI-breaking contract changes.

## Future Backlog
- Remote tmux session discovery over SSH (opt-in with host allow/deny controls): `docs/specs/remote-tmux-ssh-discovery.md`.
